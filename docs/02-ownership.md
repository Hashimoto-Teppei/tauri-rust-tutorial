# 第2章 所有権と借用

Rust 学習最大の山場です。ここを越えれば残りは「便利な型システムの勉強」です。

## 2.1 なぜ必要か

| 言語 | メモリ解放の方法 |
|---|---|
| TS / Python | GC が「誰も参照していない」ことを実行時に判定して回収 |
| C / C++ | プログラマが手動で free |
| **Rust** | **コンパイル時に「誰が持ち主か」を決め、持ち主がスコープを抜けたら自動解放** |

GC がないので実行時オーバーヘッドが小さく、性能が予測しやすくなります（なお Tauri が Electron より軽い主因は、Chromium を同梱せず OS の WebView を使う点です。フロントの JS には今まで通り GC があります）。

## 2.2 所有権の3ルール

1. 各値は **所有者（owner）** となる変数をちょうど1つ持つ
2. 所有者がスコープを抜けると値は破棄される
3. 代入や関数への受け渡しで、所有権は **ムーブ（移動）** する

```rust
let a = String::from("hello");
let b = a;              // 所有権が a → b にムーブ
println!("{a}");        // ❌ コンパイルエラー: a はもう使えない
```

TS では `b = a` は同じオブジェクトへの参照のコピーですが、Rust では **a が無効になります**。2つの変数が同じデータの持ち主になり、二重解放が起きるのを防ぐためです。

```rust
fn take(s: String) { }  // s の所有権を受け取る
let s = String::from("x");
take(s);
take(s);                // ❌ 1回目でムーブ済み
```

### Copy な型は例外

`Copy` トレイトを実装した型（`i32`, `f64`, `bool`, `char`、それらだけからなるタプルなど）は代入でコピーされます（ムーブにならない）。`String` や `Vec` は Copy ではありません。

### clone：明示的な深いコピー

```rust
let b = a.clone();      // ヒープ上のデータを複製。a も b も使える
```

> 初心者のうちは **迷ったら clone** で構いません。動くものを作ってから最適化しましょう。

## 2.3 借用（参照）

毎回所有権を渡したり clone したりするのは不便なので、「貸す」ことができます。

```rust
fn len(s: &String) -> usize { s.len() }  // & = 不変参照（読み取り専用で借りる）

let s = String::from("hello");
let n = len(&s);
println!("{s}");        // ✅ 貸しただけなので s はまだ使える
```

```rust
fn shout(s: &mut String) { s.push('!'); }  // &mut = 可変参照

let mut s = String::from("hi");
shout(&mut s);
```

### 借用のルール（これがすべて）

> ある時点で、**「不変参照をいくつでも」または「可変参照をちょうど1つ」** のどちらか。

```rust
let mut v = vec![1, 2, 3];
let first = &v[0];      // 不変参照
v.push(4);              // ❌ 可変操作。first が生きている間は不可
println!("{first}");
```

なぜダメか：`push` で Vec がメモリを再確保すると `first` が解放済みメモリを指す（ダングリングポインタ）。JS では起こり得ない種類のバグを、Rust はコンパイル時に防いでいます。
マルチスレッドでのデータ競合も同じルールで防がれます（第5章）。

## 2.4 String と &str

| 型 | 意味 | 例えると |
|---|---|---|
| `String` | ヒープ上の、所有された、伸縮可能な文字列 | 自分の持ち物 |
| `&str` | どこかにある文字列の一部への借用（スライス） | 借りたものを見ている |

```rust
let owned: String = String::from("hello world");
let slice: &str = &owned[0..5];     // "hello"
let literal: &str = "static";       // 文字列リテラルは &'static str
```

> **`len()` と `[a..b]` はバイト単位** です。日本語1文字は UTF-8 で3バイトなので `"日本語".len()` は 9、`&"日本語"[0..2]` は文字の途中を切るため panic します。文字数は `s.chars().count()`、先頭 n 文字は `s.chars().take(n).collect::<String>()` を使います。

**関数の引数は `&str` で受けるのが定石。** `&String` は自動的に `&str` に変換される（Deref 型強制）ので、どちらも渡せます。
**戻り値で新しい文字列を作るなら `String`。**

同様に `Vec<T>` に対する `&[T]`（スライス）があります。引数は `&[T]` で受けるのが定石です。

## 2.5 ライフタイム

参照を返す関数では、「戻り値の参照はどの引数から借りたものか」をコンパイラが知る必要があります。

```rust
fn longest(a: &str, b: &str) -> &str { ... }   // ❌ a と b どちら由来か不明
fn longest<'a>(a: &'a str, b: &'a str) -> &'a str { ... }  // ✅
```

`'a` は「a と b が両方生きている期間」という意味のラベルです。実行時には何もしません。
ほとんどの場合は **省略規則** により書かなくて済みます（引数が参照1つだけ、または `&self` メソッドなど）。

> Tauri アプリ開発で明示的なライフタイムを書く場面はほぼ `State<'_, T>` だけです。深追いは不要です。

## 2.6 所有権の判断フロー

関数の引数をどうするか迷ったら：

1. 読むだけ → `&T`（`&str`, `&[T]`）
2. 書き換える → `&mut T`
3. 保存する／別スレッドへ送る／消費する → `T`（所有権を受け取る）
